# Architecture

GooseCalc follows a clean, layered architecture with strict separation between Goose (UI logic) and C (platform/rendering).

## File Layout

```
/GooseCalc/
├── docs/                      # This documentation
├── src/                       # Goose source files (9 modules)
│   ├── calc_main.goose        # Entry point; only file with `export fn`
│   ├── calc_bridge.goose      # FFI boundary (imports `ffi`)
│   ├── calc_layout.goose      # Layout constants, Rect/UIState, compute()
│   ├── calc_hit.goose         # Pure hit-testing against Layout
│   ├── calc_dispatch.goose    # Action enum, button table, apply()
│   ├── calc_draw.goose        # All drawing functions
│   ├── calc_state.goose       # Calculator state machine (evaluate)
│   ├── calc_format.goose      # f64 → string formatting
│   └── calc_history.goose     # Ring buffer history (32 entries)
├── main.c                     # C entry point; Android NativeActivity glue
├── crash.c / crash.h          # Native crash reporter (signal handlers)
├── font8x8.h                  # Bitmap font data (IBM VGA 8x8)
├── calc_main.h                # Generated by Goose compiler (FFI header)
├── calc_main.c                # Generated by Goose compiler (C translation)
├── AndroidManifest.xml.template # Manifest template (envsubst variables)
├── Makefile                   # Build rules
├── Makefile.minimal           # Minimal build variant
├── VERSION                    # Version string (e.g. "0.2.4")
├── my-release-key.keystore    # Signing keystore
└── rawdrawandroid/            # Vendored C framework
    ├── Makefile
    ├── android_native_app_glue.c/h
    ├── CNFGAndroid.h
    ├── test.c
    └── rawdraw/               # Core rawdraw library
```

## Import Graph (Acyclic)

```
calc_main.goose  ──┬──> calc_bridge.goose
                   ├─> calc_state.goose ──> calc_format.goose ──> calc_bridge.goose
                   ├─> calc_history.goose ──> calc_bridge.goose
                   ├─> calc_layout.goose
                   ├─> calc_hit.goose ──> calc_layout.goose
                   ├─> calc_dispatch.goose ──> calc_state.goose
                   │                          ├─> calc_history.goose
                   │                          └─> calc_layout.goose
                   └─> calc_draw.goose ──> calc_bridge.goose
                                      ├─> calc_layout.goose
                                      ├─> calc_state.goose
                                      ├─> calc_history.goose
                                      ├─> calc_format.goose
                                      └─> calc_dispatch.goose
```

**Rule:** Only `calc_bridge.goose` imports `ffi`. Only `calc_main.goose` exports functions to C. The graph is fully acyclic and can be verified with `grep`.

## Module Responsibilities

### calc_main.goose (Orchestrator)
- Holds global state: `g_state`, `g_history`, `g_ui`, `g_show_crash`
- Exports all entry points called from C:
  - `goose_reset()` — reset state for fresh Activity
  - `goose_init(argc, argv)` — initialize (crash check + history load)
  - `goose_handle_touch(x, y, bDown)` — touch event handler
  - `goose_draw()` — render frame
  - `goose_handle_back()` — back button
  - `goose_force_resize()` — invalidate layout on rotation
  - `goose_exit()` — save history on clean exit

### calc_bridge.goose (FFI Boundary)
- Imports `ffi` — **the only Goose file that does**
- Wraps all C functions with safe i32/u32-only wrappers
- Key wrappers: `draw_rect`, `draw_segment`, `set_color`, `draw_text`, `text_width`
- `draw_text()` uses an i32 byte-by-byte protocol — no pointers or slices cross FFI
- `screen_w()`/`screen_h()` query Android dimensions
- `data_path()`, `crash_text()`, `crash_len()`, `crash_clear()` bridge to C crash reporter

### calc_layout.goose (Geometry)
- `Rect` struct: `x1, y1, x2, y2` (f32)
- `Layout` struct: 20 button rects + history panel + width/height
- `UIState` struct: layout + history visibility + pressed button + flash counter
- `compute(w, h)` — calculates button grid and history panel from screen dimensions
- Constants: `BTN_COLS=4`, `BTN_ROWS=5`, `BTN_COUNT=20`, `DISPLAY_H_FRAC=0.20`

### calc_hit.goose (Hit Testing)
- `button_at(lay, x, y)` — returns button index (0-19) or -1
- `in_hist_close(lay, x, y)` — tests close button in history panel
- `in_hist_panel(lay, x, y)` — tests if point is inside history panel

### calc_dispatch.goose (Action Logic)
- `Action` enum: `None`, `Digit{d}`, `Decimal`, `Add`, `Sub`, `Mul`, `Div`, `Equals`, `Clear`, `History`, `DismissCrash`
- `action_for(i)` — maps button index (0-19) to Action
- `label_for(i)` — maps button index to display label ("7", "+", "C", etc.)
- `build_history_entry()` — constructs "left op right = result" strings (128-byte buffer)
- `apply(state, hist, ui, a)` — dispatches actions to state/history/UI mutations

### calc_state.goose (State Machine)
- `CalcState` struct: display, accumulator, pending_op, error flag, decimal mode, etc.
- Chained (desk-calculator) semantics: `2 + 3 * 4 = 20`, not 14
- `input_digit()`, `input_decimal()`, `input_op()`, `evaluate()`, `evaluate_pending()`
- Division by zero → error state
- `get_display()` — returns "left op " while waiting for operand, otherwise current value
- `format_number()` routing: fixed-point, scientific, or Error/Infinity strings

### calc_format.goose (Number Formatting)
- `format_dec(v)` — fixed-point with single rounding step (avoids binary→decimal artifacts)
- `format_sci(v)` — scientific notation for |v| >= 1e16 or |v| < 1e-9
- Trailing zeros trimmed, max 16 display characters
- Handles NaN, +Inf, -Inf

### calc_history.goose (History Ring Buffer)
- 32-entry ring buffer of `HistoryEntry { text[128], ok }`
- `history_push()` — adds entry, overwrites oldest when full
- `history_save()` / `history_load()` — stubbed (persistence disabled)

## C Layer (main.c + crash.c)

### main.c
- `int main(argc, argv)` — entry point matching rawdrawandroid's `android_main` glue
- Reads previous crash log before `crash_reporter_init()` truncates it
- Initializes crash reporter, Goose runtime, graphics (`CNFGSetupFullscreen`), audio (OpenSL ES)
- Main render loop: `CNFGHandleInput()` → `goose_draw()` → `CNFGSwapBuffers()`
- `HandleDestroy()`, `HandleSuspend()`, `HandleResume()`, `HandleKey()`, `HandleButton()` — Android event callbacks
- `goose_draw_rect()` — C shim: casts int args to float for `CNFGTackRectangle` (works around Goose f32 ARM64 bug)
- `goose_text_clear/append/draw/width()` — bitmap font staging buffer (640 bytes)
- `draw_char_bmp()`, `draw_text_bmp()`, `text_width_bmp()` — font8x8 glyph rendering
- `sound_click()` — 60ms 1800Hz sine wave click via OpenSL ES

### crash.c
- Signal handlers for `SIGSEGV`, `SIGABRT`, `SIGBUS`, `SIGFPE`, `SIGILL`
- Writes fault address, PC, LR, SP to crash log
- `crash_reporter_init()` — opens log file, installs signal handlers
- `crash_clear()` — deletes log on clean exit (prevents false crash on next launch)
- `crash_read()` — reads log content for Goose-side display

## CNFG Graphics (rawdrawandroid)

All drawing uses `CNFGTackRectangle()` for filled rects and `CNFGTackSegment()` for lines. Text uses the bundled `font8x8` bitmap font rendered as filled rectangles per set bit.

Colors are `0xRRGGBBAA` (32-bit RGBA).

## Visibility / Symbol Export

C functions called from Goose use `__attribute__((visibility("default")))`:
- `get_CNFGPenX/Y`, `set_CNFGPenX/Y`
- `get_android_width/height`
- `get_data_path`, `get_crash_text`, `get_crash_len`
- `clear_crash`
- `goose_draw_rect`, `goose_text_clear/append/draw/width`

Goose functions exported to C (via `calc_main.h`):
- `goose_draw`, `goose_handle_touch`, `goose_handle_back`, `goose_force_resize`, `goose_init`, `goose_exit`, `goose_reset`
